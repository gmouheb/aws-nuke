# NukeConfigs

This repository contains `aws-nuke` configuration files used to clean AWS accounts in a controlled way.

## What is aws-nuke?

`aws-nuke` is a command-line cleanup tool for AWS accounts. It scans the account and lists resources it can remove, based on a YAML config that defines:

- the target account
- the AWS regions to scan
- resource filters and exclusions

## Prerequisites

- AWS CLI v2
- AWS SSO access to the target account
- `aws-nuke` binary
- A verified AWS account ID before any execution

## 1. Install AWS CLI

AWS CLI v2 is required for SSO.

```bash
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip
unzip awscliv2.zip
sudo ./aws/install
```

Check the installed version:

```bash
aws --version
```

Example:

```text
aws-cli/2.34.1 Python/3.13.11 Linux/5.15.0-139-generic exe/x86_64.ubuntu.20
```

## 2. Configure AWS SSO

Run:

```bash
aws configure sso
```

Provide values similar to:

- `SSO Start URL`: `https://XXXXXXX.awsapps.com/start/`
- `SSO Region`: `eu-central-1`
- `Account`: `example-stg`
- `Role`: `AWSAdministratorAccess`
- `Profile name`: `example-stg`

## 3. Login with SSO

```bash
aws sso login --profile example-stg
```

## 3.1 Alternative: Using Access Keys

If you are not using SSO, you can authenticate using static AWS credentials.

**Method 1: Using Environment Variables (Recommended for one-off runs)**

```bash
export AWS_ACCESS_KEY_ID="AKIAIOXXXXXXXXXXXXXXXXXXX"
export AWS_SECRET_ACCESS_KEY="wJalrXUtnFEMI/KXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"
export AWS_DEFAULT_REGION="eu-central-1"
```

*(Note: If you are using temporary credentials generated by STS, you will also need to export `AWS_SESSION_TOKEN`.)*

**Method 2: Using an AWS Profile**

Edit or create `~/.aws/credentials`:
```ini
[example-stg-keys]
aws_access_key_id = AKIAIOSFODNN7EXAMPLE
aws_secret_access_key = wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

Then append `--profile example-stg-keys` to your `aws-nuke` and `aws` CLI commands instead of the SSO profile.

## 4. Verify the Account ID (Mandatory)

Always verify the authenticated account before running `aws-nuke`.

```bash
aws sts get-caller-identity --profile example-stg
```

Expected output:

```json
{
  "Account": "169466541366"
}
```

## 6. Create an AWS Account Alias

Check whether an alias already exists:

```bash
aws iam list-account-aliases --profile example-stg
```

If no alias exists, create one:

```bash
aws iam create-account-alias --account-alias example-stg --profile example-stg
```

Verify again:

```bash
aws iam list-account-aliases --profile example-stg
```

## 7. Create the aws-nuke Config

Example file: `ConfigExampleStg.yaml`

```yaml
regions:
  - eu-central-1
  - eu-west-1
  - us-east-1

# The blocklist is a list of account IDs that aws-nuke is not allowed to run against.
# Its purpose is to prevent accidental execution on the wrong account.
# aws-nuke operates against the AWS account your credentials authenticate to,
# together with the account-specific configuration under `accounts`.
# For example, if your active credentials resolve to account "169466541366",
# aws-nuke will act in that account's context, subject to the config.
# Other accounts are not directly targeted unless you intentionally authenticate
# to them and configure them.
account-blocklist:
  - "Account-ID1"
  - "Account-ID2"
  - "Account-ID3"
  - "..."

# Protect IAM, SSO, federation, and org-related access components.
resource-types:
  excludes:
    - IAMUser
    - IAMUserAccessKey
    - IAMUserPolicyAttachment
    - IAMPolicy
    - IAMRole
    - IAMRolePolicy
    - IAMRolePolicyAttachment
    - IAMSAMLProvider

accounts:
  "12345678901": {}
```

Notes:

- `account-blocklist` prevents execution against protected accounts.
- `accounts` should contain only the account ID you intend to target.
- IAM-related exclusions reduce the risk of deleting access-critical resources.

## 8. Validate the Configuration

Run both commands before any nuke execution:

```bash
aws-nuke explain-account --config ConfigExampleStg.yaml --profile example-stg
aws-nuke explain-config --config ConfigExampleStg.yaml --profile example-stg
```

## 9. Dry Run (Safe)

Use a dry run first:

```bash
aws-nuke run --config ConfigExampleStg.yaml --profile example-stg --no-dry-run=false
```

When prompted, type the account alias:

```text
example-stg
```

This shows what would be deleted without applying changes.

## 10. Real Execution (Destructive)

Warning: this will delete resources.

```bash
aws-nuke run --config ConfigExampleStg.yaml --profile example-stg --no-dry-run
```

## 11. Save Output to a File

Optional:

```bash
aws-nuke run --config ConfigExampleStg.yaml --profile example-stg --no-dry-run | tee output.txt
```

This is useful for reviewing what `aws-nuke` reported.

## 12. Safety Checks

Check the account again immediately before running:

```bash
aws sts get-caller-identity --profile example-stg
```

```bash

```

```bash

```

```bash

```

## 14. Special Case: Production Accounts

If the account alias, profile, or naming contains any of the following:

- `prod`
- `prd`
- `production`

`aws-nuke` blocks execution by default as a safety mechanism.

To proceed, explicitly bypass the alias check.

Add this block to the YAML config:

```yaml
bypass-alias-check-accounts:
  - "prod-account-id"
```

Dry run for a production-style account:

```bash
aws-nuke run --config ConfigExamplePrd.yaml --profile example-prod --no-alias-check --no-dry-run=false
```

Real execution after full validation:

```bash
aws-nuke run --config ConfigExamplePrd.yaml --profile example-prod --no-alias-check --no-dry-run
```

This bypasses the alias safety check, so use it only after confirming the account ID and config.

## 15. aws-nuke Output Explanation

- `would remove`: The resource is a real deletion candidate under the current config. In dry-run mode, it is only reported.
- `filtered`: The resource was discovered but will be skipped because of filters, exclusions, or built-in protection logic.
- `Total`: The total number of resources discovered in scope.
- `nukeable`: The resources currently considered deletable. In practice, this usually matches `would remove`.
- `trigger to remove`: Real deletion happens when you run `aws-nuke run ... --no-dry-run` and confirm the alias when prompted.

## 16. Key Notes

- `aws-nuke` only affects the authenticated account.
- Always run a dry run before real execution.
- Always verify the AWS account ID before any destructive step.
- `aws-nuke` aborts by default if the alias contains production-related terms.
- To override production alias protection:
  - add the account ID under `bypass-alias-check-accounts`
  - pass `--no-alias-check` in the command

## 17. Quick Summary

- Use AWS SSO or secure Access Keys for authentication.
- Lock the config to one account.
- Verify the account ID every time.
- Run a dry run before deletion.
- Use alias confirmation as a safety check.
